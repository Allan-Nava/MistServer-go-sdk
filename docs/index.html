Why

The controller API, without the plumbing

MistServer exposes everything through one JSON endpoint and a login handshake. This SDK turns that into Go methods with request and response types.

Auth handled

The challenge round-trip and hashed password are done for you, and reused for a minute so calls don't pay for a second request.

Typed payloads

Structs for streams, auto-pushes, push lists and server config, so the compiler catches a misspelt field before MistServer does.

Bring your own client

Pass in your own resty client and zap logger, so timeouts, TLS, retries and log format stay under your control.

Quickstart

From zero to a live restream

The controller API usually listens on :4242/api. Point the client at it with the admin credentials you set in MistServer.

  1. Installgo get the module. Go 1.23 or newer.
  2. ConfigurePass a resty client, a sugared zap logger, and the With… options.
  3. CallEvery method logs in on its own; you just send the request.
main.go
package main

import (
    "fmt"
    "log"

    mist "github.com/Allan-Nava/MistServer-go-sdk/mist"
    "github.com/go-resty/resty/v2"
    "go.uber.org/zap"
)

func main() {
    logger, _ := zap.NewProduction()
    defer logger.Sync()

    client := mist.NewService(
        resty.New(),
        logger.Sugar(),
        mist.WithBaseURL("http://localhost:4242/api"),
        mist.WithUsername("admin"),
        mist.WithPassword("secret"),
    )

    pushes, err := client.PostPushList(mist.PostPushListRequest{PushList: true})
    if err != nil {
        log.Fatal(err)
    }
    fmt.Println(len(pushes.PushList), "active pushes")
}

API

What the client covers

Each method maps to one MistServer API command. Field-level docs are on pkg.go.dev; command semantics are in the MistServer API reference.

MethodCommandWhat it does
Health()authorizeLogs in and returns the server config and configured streams. A cheap liveness and credentials check.
PostStream(req)addstreamCreates or updates one or more streams: name, source, DVR window, debug level.
PostStreamRemove(req)deletestreamDeletes a stream by name.
PostAutoPush(req)push_auto_addAdds a rule that pushes a stream to a target every time it comes online.
PostAutoPushRemove(req)push_auto_removeRemoves auto-push rules for a stream.
PostPushList(req)push_listLists the pushes that are running right now.
PostPushStop(req)push_stopStops running pushes by ID (IDs come from PostPushList).

Auth

Challenge-response, done once a minute

MistServer never receives the plain password. The first request fetches a challenge; the SDK answers with md5(md5(password) + challenge) and reuses that answer for the next 60 seconds, behind a mutex, so concurrent calls share it.

MD5 is what the MistServer protocol specifies. Put the API behind TLS or a private network if it leaves the host.
